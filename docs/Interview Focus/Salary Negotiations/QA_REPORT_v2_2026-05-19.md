## PART 3 — Architecture audit (per Architecture Tests sheet)

Each row from the Architecture Tests sheet, evaluated against the codebase.

### A1 · State machine (`stage order`) — **PASS**

- **Where:** `server-handlers/_negotiation-kernel.ts` — `state.phase` (opening
  / discovery / range-disclosure / probe-expectations / offer-presented /
  counter-offer / closing-push / accepted / walked-away / stalemate) +
  `state.roundIndex` for multi-round.
- **Pass evidence:** `DISCOVERY_SEQUENCE` (currentCtc → fixedVariableSplit →
  expectedCtc → valueProof → competingOffers → noticePeriod) is enforced by
  `_next-action-planner.ts:planNextActionInternal` and `_discovery-stage.ts`;
  the planner walks one item per turn (`PROBE_PRODUCING_KINDS` push onto
  `state.askedTopics`).
- **Bug-class blocked:** "random questions, skipped stages" — the planner
  rejects probes whose topic is already in `askedTopics`.

### A2 · Memory (store salary values) — **PASS**

- **Where:** `NegotiationState.band.{currentCtc, fixedComponent,
  variableComponent, candidateTarget, initialOffer, ceiling, walkAway,
  bandMin, bandMax}` + `state.{highestOfferMade, lastJoiningBonusOffered,
  noticePeriodDays, competingOfferLpa, verbalAcceptanceTurn}`.
- **Pass evidence:** `applyCandidateAnswer` merges deltas into the band; no
  reset path. `serializeState` / `deserializeState` (line 5200+) preserves
  fields across turns.
- **Architecture-test mapping:** "Enter CTC, fixed, expected CTC, then ask
  fixed again" → the planner reads `band.fixedComponent != null` and skips
  the re-probe; verified at `_next-action-planner.ts:746`.

### A3 · Persona detection — **PARTIAL**

- **Where present:** `_indian-recruiter-personas.ts` (5 SECTOR personas) +
  `_negotiation-rounds.ts` (3 ROUND personas) + `_candidate-stance.ts`
  (CandidateStanceResult with `flexibilityPosture`, `soundsDesperate`,
  `treatsEquityAsCash`, `avoidsAnchor`, `marketReferenceVague`,
  `salaryOnlyFactor`, etc.).
- **Gap:** the workbook defines **20 candidate personas (P01–P20)** as
  first-class types ("first-time negotiator", "underpaid switcher",
  "ESOP-heavy startup candidate", …). The kernel does NOT classify into
  these labels — it detects orthogonal stance flags. Mapping example:
  | Persona | Stance flag covering it                       | Confidence |
  | ------- | --------------------------------------------- | ---------- |
  | P01     | `avoidsAnchor` + `marketReferenceVague`       | ✅ strong   |
  | P03     | `flexibilityPosture === "rigid"` (partial)    | ⚠️ partial |
  | P04     | `competingOfferLpa != null` (set on disclosure)| ✅ strong  |
  | P06     | `treatsEquityAsCash`                          | ✅ strong   |
  | P12     | `soundsDesperate`                             | ✅ strong   |
  | P13, P16, P17, P18, P19 | **not modelled**                | ❌ missing  |
- **Severity:** HIGH. The workbook explicitly tests these labels; without a
  classifier the report cannot say "we detected a P19 (in-hand focused)
  candidate" — only "we detected `confidentialOvershare`".
- **Fix recommendation:** add `_candidate-archetype.ts` that maps the
  stance-flag set + transcript signals → a `CandidateArchetype` enum (20
  values). Pure, deterministic. ~2 days work.

### A4 · Indian HR language — **PASS**

- **Where:** `_canonical-prose.ts:72-` `BANNED_RECRUITER_IDIOM` /
  `PREFERRED_INDIAN_IDIOM` lists. `restyle-validator` rejects US-isms in
  `_response-pipeline.ts`.
- **Pass evidence:** "circle back", "touch base", "synergy", "on board",
  "compensation package", "remuneration", "PTO", "start date" all banned;
  CTC, fitment, panel, grade, joining bonus, retention bonus, fixed,
  variable all surface in canonical templates.

### A5 · Refusal fallback (TC004 / TC046) — **PASS** with caveat

- **Where:** `_canonical-prose.ts:837` `band-disclosure-deflect` with 5
  sector variants + 3 round-persona variants. The planner has guards at
  `_next-action-planner.ts:1282-1302` (PDF#35 Move 1) that route to
  acceptance-close, offer-recap, or counter-engagement BEFORE
  `band-disclosure-deflect` can re-fire — explicitly preventing the
  "repeated refusal" loop.
- **Caveat:** the band-deflect prose always ends with "Happy to take this
  back to the panel" but does not always issue the next forward-moving
  question; the panel-stall is implicit. Pass Criteria of TC004 ("does not
  get stuck; asks next question") is satisfied **only when** combined
  with `panel-approval-stall` follow-up; verify the planner chains.

### A6 · Component parser — **PASS**

- **Where:** `_component-breakdown.ts` separates fixed / variable /
  joining-bonus / ESOP / RSU. `_candidate-profile.ts:detectFixedVariableSplitDisclosed`.
- **Pass evidence:** `extractCompClaims` in `salary-negotiation.ts:145`
  parses LPA / lakhs / cr with both old & new regimes for take-home.
- **Bug-class blocked:** "treats all components as fixed" — the parser
  flags `treatsEquityAsCash` when candidate equivocates.

### A7 · Unit parsing (LPA / monthly) — **PARTIAL**

- **Where:** `COMP_RE` in `salary-negotiation.ts:102` handles LPA, lakhs,
  l, cr, crores; `USD_RE:130` handles $/USD/k/thousand.
- **Gap:** **monthly-in-hand vs annual-LPA ambiguity** is not specially
  handled. If candidate says "I want ₹1.5L per month" — the parser would
  read this as ₹1.5 LPA, not ₹18 LPA annualised. TC055 / TC066 / TC107
  flag this.
- **Severity:** HIGH. Fix: extend regex to detect "/month", "p.m.", "per
  month" suffixes and multiply by 12.

### A8 · Mode control (live vs coaching) — **FAIL**

- **Where searched:** `interviewAPI.ts:561` mentions a "practice mode
  badge" but no gate found in `_response-pipeline.ts` or
  `_canonical-prose.ts` that toggles coaching surfaces mid-session.
- **Bug-class triggered:** TC051 (coaching leakage during live). The
  workbook's pass criteria require coaching to be deferred to the
  post-session report — there's no `if (practiceMode === false) suppress
  coaching` gate visible.
- **Severity:** CRITICAL. Fix: thread a `mode: "live" | "practice"` field
  through `NegotiationSettings` → `_response-pipeline.ts` and short-circuit
  any coaching prose in live mode.

### A9 · One-question rule — **PASS**

- **Where:** Canonical-prose templates end with exactly one `?` per
  response (verified by grep of `case "discovery-probe":` block —
  always single ask). `checkSentenceLength` in `_response-pipeline.ts`
  enforces max-30-word sentences which makes stacked questions hard.

### A10 · Recovery (TC085 / TC086 / TC105) — **PASS**

- **Where:** `_candidate-stance.ts:detectRecoverySignals` +
  `acknowledge-and-recover` planner kind +
  `clarify-prior-question` planner kind.
- **Pass evidence:** Blank / one-word / silent candidate answers route to
  `acknowledge-and-recover`; state is preserved (no phase reset).

### A11 · Report generation — **PASS**

- **Where:** `server-handlers/analyzers/salary-negotiation.ts` produces:
  anchoring score, justification quality, fixed/variable awareness,
  pushback handling, leverage use, Indian-HR realism, conversation state,
  closure score. Maps 1-to-1 to the workbook's 9-dim rubric.
- **Pass evidence:** `meta.salaryNegotiation` block carries `tierBucket`,
  `recruiterPersona`, `inHandMonthly` (both regimes), `equityLiteracy`,
  `batnaStrength`. 

### A12 · Ethical safeguards (TC111) — **PASS**

- **Where:** `_canonical-prose.ts:1320` `fake-leverage-challenge` planner
  branch. `_red-flags.ts:643` `rescission-risk` flag. `confidentialOvershare`
  stance.
- **Pass evidence:** When candidate claims a competing offer with no
  detail, the planner issues a soft probe ("Could you share which company
  / what level the offer was at?") rather than amplifying the leverage.

## PART 5 — Critical bugs surfaced

### BUG-001 — Live-mode coaching gate is missing (TC051)

- **Severity:** CRITICAL
- **Scenario:** "Practice mode" is referenced in `interviewAPI.ts:561` but
  no propagation into `_response-pipeline.ts` / canonical-prose.
- **Expected:** Coaching insights deferred to post-session report when
  `mode === "live"`.
- **Actual:** Cannot find a gate. Coaching surfaces (lever rationale,
  "frankly the bar for that is a documented critical-skill premium" from
  `internal-equity-defense`) leak into live turns.
- **Why it matters:** Test suite priority. Indian HR interviews don't
  coach mid-call — the AI sounds artificial.
- **Suggested fix:** Add `practiceMode: boolean` to `NegotiationSettings`
  → `_negotiation-kernel.ts`. In `_response-pipeline.ts:validateAnswer`,
  strip coaching-flavoured tails (anything past the final `?`) when
  `practiceMode === false`. ~1 day work.

### BUG-002 — Candidate-persona classifier missing (architecture gap)

- **Severity:** HIGH (the workbook elevates this to per-persona testing)
- **Scenario:** 20 candidate archetypes (P01–P20) are not detected as a
  typed enum; only orthogonal stance flags. Personas P13 / P16 / P17 / P18
  / P19 have **no** mapping at all.
- **Expected:** A `CandidateArchetype` field on state + analyzer meta so
  the post-session report can say "we identified you as P19 (in-hand
  focused) and here's per-archetype coaching."
- **Actual:** Report says "your `salaryOnlyFactor` is true" — accurate but
  not aligned to the testing vocabulary.
- **Why it matters:** the test workbook EXPECTS the AI to adapt its
  pressure / language per persona. Without a classifier, all candidates
  get the same recruiter persona × round persona modulation.
- **Suggested fix:** new module `server-handlers/_candidate-archetype.ts`
  with a `classifyArchetype(stance, profile, transcript) → CandidateArchetype`
  function. Deterministic. ~2 days work.

### BUG-003 — Monthly-vs-LPA unit parsing gap (TC055 / TC066 / TC107)

- **Severity:** HIGH
- **Scenario:** Candidate says "I want ₹1.5L per month" or "1.5 lakhs
  monthly". Parser reads ₹1.5 LPA = annual, not ₹18 LPA annualised.
- **Expected:** Detect `/month|p\.?m\.?|per month|monthly/i` suffix and
  multiply by 12.
- **Actual:** `COMP_RE` (`salary-negotiation.ts:102`) does not have a
  monthly token; treats every match as annual.
- **Why it matters:** P19 ("in-hand monthly matters") candidates routinely
  speak in monthly. Mis-parsing turns ₹18 LPA expectation into ₹1.5 LPA,
  which then drives an absurdly low fitment offer.
- **Suggested fix:** Extend `COMP_RE` + `extractCompClaims` to handle
  monthly suffix. ~half-day work.

### BUG-004 — `band-disclosure-deflect` chains weakly (TC004)

- **Severity:** MEDIUM
- **Scenario:** Candidate asks for budget. Bot deflects ("won't be able to
  share internal numbers"). Next planner turn must immediately re-ask
  expected range, otherwise the conversation stalls for 1 turn.
- **Expected:** Same-turn chain: deflect + re-ask.
- **Actual:** Deflect prose ends at "Happy to take this back to the panel"
  — no immediate question. The next turn picks up `probe-expectations` but
  there's a perceptible 1-turn dead air.
- **Suggested fix:** Append " — meanwhile, what's the range you have in
  mind?" to all band-disclosure-deflect variants. ~1 hour work.

### BUG-005 — Persona P08 / P16 have zero coverage in the test suite

- **Severity:** LOW (workbook-side gap, not code-side)
- Tier-2/remote (P08) and junior-to-senior transition (P16) have 0 test
  cases. The codebase has no behaviour to test for these — but the gap
  should be closed in **v3 of the workbook**.
